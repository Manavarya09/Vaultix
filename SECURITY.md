# Security

We take security seriously. If you discover a vulnerability, please follow these responsible disclosure guidelines so we can respond promptly and coordinate a fix.

How to report

- Preferred: email security@your-domain.example with the subject "Security vulnerability: [repo-name]".
- If email is not possible, open a private GitHub security advisory (if available) or contact a maintainer directly.

What to include

1. Affected component (backend, frontend, worker, etc.) and version/commit SHA.
2. A short summary of the issue and its impact.
3. Step-by-step reproduction instructions or a minimal PoC.
4. Any logs, screenshots, or network traces that help reproduce.
5. Your contact information for follow-up.

Handling & timeline

- We will acknowledge receipt within 3 business days.
- We aim to provide a security assessment and remediation plan within 14 calendar days for critical issues.
- We may request additional information or ask for help validating a patch.
- Once fixed, we will coordinate disclosure and credit with the reporter, unless they request anonymity.

Public disclosure

- Do not publicly disclose the vulnerability until a fix has been released and coordinated with the maintainers.

Sensitive data

- Do not include sensitive data (passwords, private keys) in public issue trackers or emails. If you must send sensitive material, indicate how it should be handled or provide a PGP/GPG key.

Third-party dependencies

- If the issue is in a third-party dependency, we will coordinate with the dependency maintainers and follow their disclosure process as needed.

Credits

- We will credit reporters for their responsibly disclosed vulnerabilities unless they ask to remain anonymous.
